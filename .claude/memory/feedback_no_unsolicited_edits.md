# 严禁未经明确指示修改代码 & 绝不自作主张删除已有代码

用户明确强调：除非用户明确要求修改某段代码，否则绝对不要自行修改。

典型案例：用户指出 `def tag_algorithm(address, tag)` 函数，AI 擅自修改后导致代码出问题。

**规则：只做用户要求的修改，不多做不少。不要自作主张优化、重构或改动任何代码。**

## 新增功能时绝不可删除已有字段

在添加新字段/新方法时，绝不可删除已有的字段或方法，即使它们看起来"被替换"了。

**严重事故：** 在 `app/entities/app_user.rb` 中新增 `parental_enabled` 时，擅自删掉了已有的 `has_password` 字段，导致前端依赖的字段丢失。

**铁律：**
- 新增功能只能**添加**代码，不能**删除**已有代码
- 如果用户说"把 A 改成 B"，默认理解为**增加 B**，保留 A，除非用户明确说"删掉 A 换成 B"
- 涉及 entity/entity expose 字段的修改，尤其要谨慎，前端可能依赖任何已有字段
